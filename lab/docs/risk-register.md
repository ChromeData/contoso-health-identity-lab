# Identity risk register (lab scenario)

**Status:** Draft · **Date:** 2026-10-20 · **Scope:** Contoso Health, the
lab's fictional 5,000-user hospital. **Risk acceptor:** CISO.

Ratings are judgement, not measurement. **Likelihood / Impact:** H / M / L.
**Residual** is the rating after the controls the lab already has, assuming
they are applied as written (staging flags on, policies in the state the code
gives them, which for Conditional Access is 9 of 11 enforced, CA002 and CA021 report-only).
The tenant exists and 64 reviewed changes are applied (`lab/evidence/capture-log.csv`);
a control with no E row is still design evidence, not operating evidence.

**Status words used in the controls column:**

- **RAN · harness** — ran end to end in a local harness on 2026-10-20,
  never against a tenant: the PAM harness against a Samba AD DC
  (`lab/pam/test/e2e.sh`, 284/284), the 500-account scale run
  (`test/e2e-scale.sh`, 79/79), the midPoint certification campaign
  (`test/e2e-midpoint.sh`, 91/91), Vault dynamic database credentials
  (`test/e2e-dynamic-db.sh`, 60/60) and Kubernetes workload identity on
  kind (`lab/k8s/`, 64/64). Their hashed run records are in `lab/evidence/`
  (index: `lab/evidence/README.md`). **RAN · tenant:** nothing yet.
- **BUILT** — code that passes its offline tests (`terraform validate`,
  mocked `terraform test`, Pester, structural checks) but has never run
  against Entra, Azure or Sentinel.
- **DESIGNED** — written down only.

## How this register is used

- **High residual** (R01, R03, and R09 for the single DC) needs a dated plan
  or a signed acceptance with an expiry. R01 is accepted for the lab today, as
  a time-boxed risk acceptance (`adr/0005-risk-acceptance-apply-identity-tier0.md`),
  with the inline notes in `lab/terraform/envs/bootstrap/main.tf` and
  `lab/terraform/README.md` (Security notes). That acceptance does not carry
  into production, and it covers `AppRoleAssignment.ReadWrite.All` only
  while `enable_app_management_roles` is on.
- **Built is not closed.** A control marked BUILT or RAN above lowers the
  rating only on the assumption that it is applied as written. Each one has
  an evidence capture in `evidence-capture-plan.md`; the rating is revisited
  when that capture exists.
- Each risk is reviewed on its review date and after any incident, any
  change to a control listed above, or any new CI identity.
- Closing a risk needs evidence from the tenant (an evidence pack, a drill
  log, a report CSV), not a code change alone.
